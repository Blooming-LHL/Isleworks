# Isleworks 像素观察台、数据统计与轮次复盘方案 v0.1

- 日期：2026-11-10
- 状态：待评审；本文描述拟实施方案，不代表已经实现。
- 范围：以已验证的像素岛屿原型为主界面，补充独立的数据统计页面，以及每轮结束后的 LLM 复盘卡片。
- 参考：双原型实验记录 `/private/tmp/isleworks-visual-lab.MpxNUu/实验结论.md`；现有 [MVP 方案](自主经济模拟系统_MVP_v0.1.md)与 [实施记录](IMPLEMENTATION.md)。临时原型可能被系统清理，正式实现不能依赖该目录。

## 1. 背景与目标

已验证的像素岛屿原型可以作为首页视觉与交互的起点：用户观察活动群体、查看居民、回放日期。用户希望增加两项能力：

1. 借鉴 Mesa 的曲线与统计分析，提供一个专门的数据统计页面。
2. 每轮运行结束后，在页面最后展示一张 LLM 经济复盘卡片，包含总结和资源调整建议。

设计目标：让用户能从“岛上发生了什么”，继续追问“整体数据如何变化”和“模型怎样解释这一轮”。统计事实可追溯到归档；模型观点有证据、边界和明确状态。设计需要适应人数和动作种类增长。

本文的“像素原型可用”指用户认可其方向，并不意味着原型已是生产实现。实际经济模型目前为 6 位居民、每天 4 个劳动时段；100 和 10,000 人仅是之前的合成展示压力数据。

## 2. 现状与约束

- 像素原型位于临时目录，读取一轮已完成的基线归档；地图坐标和移动是展示示意，回放不执行模拟。
- 现有正式观察器在 `src/isleworks/interfaces/web/`，使用本地 HTTP 服务；两者尚未合并。当前详情 API 在读取时会装载运行归档、计算指标，规模增长后需实测并优化。
- `analysis.build_metrics` 已由提交的事件计算每日食物存量、产量、消耗、短缺量、纤维存量、活跃人数、交易次数、渔网制造次数等；食物内部单位为毫鱼，1,000 毫鱼 = 1 鱼。
- 日期级计划保存在归档中。原型截图右侧曲线按“当天四个劳动时段中出现最多的计划动作”统计人数，平票取计划中较早出现的动作；它不等于已执行动作或劳动时段数。
- 现有运行完成或经济坍缩时会先保存程序计算的事实报告，再按配置自动触发 LLM 复盘；模型复盘与事实报告分开保存，当前接口在最终日期提供 `facts_report` 和 `llm_review`。复盘是异步呈现的，有独立调用预算；缺少配置或失败时，世界结果和事实报告保留。
- 项目核心运行支持 Python 3.11+，当前无 Mesa 强制依赖。Mesa 3.5.1 实验采用独立 Python 3.12 环境。

## 3. 页面信息架构

建议使用同一套站点导航，保持当前像素风格、颜色和基础卡片样式：

```text
Isleworks
├── 岛屿观察（默认入口）
│   ├── 运行选择、运行状态和控制
│   ├── 像素岛屿、居民与活动群体
│   ├── 岛屿资源、近期事件
│   └── 本轮复盘卡片（页面最后）
└── 数据统计
    ├── 同一运行的时间范围与数据口径
    ├── 核心指标摘要
    ├── 食物、活动与人口趋势
    ├── 交易和生产等其他可用指标
    └── 事实数据与事件明细入口
```

默认主界面保留像素原型的布局和体验；增加“岛屿观察 / 数据统计”入口。统计页面作为独立页面或路由，具体路由由实施时确定，使用浏览器前进/后退可返回。切换页面应保留所选 `run_id`；已选择历史日期时保留该日期与所选时间范围，并允许一键回到最新。没有运行时显示创建运行入口或引导，不展示伪造数据。

## 4. 指标、口径与数据来源

第一版优先实现有明确来源和价值的统计，不因 Mesa 样例存在某条曲线就强行展示。

| 展示 | 口径 | 数据来源与现状 | 单位 |
|---|---|---|---|
| 食物存量趋势 | 每日结算后的全部居民食物之和，第 0 天为初始值 | 现有 `daily.food_stock`；与当日快照核对 | 内部毫鱼；界面转换成鱼 |
| 每日食物产出 / 消耗 | 当日 `fish` 事件带来的食物增量 / `consume` 实际消耗 | 现有 `daily.food_produced`、`daily.food_consumed`；日值非累计值 | 鱼/日 |
| 活跃居民 | 每日结算后的活跃人数 | 现有 `daily.active`，与对应快照核对 | 人 |
| 每日缺粮量 | 当日 `consume` 的缺口之和 | 现有 `daily.shortage`；缺粮量不是缺粮人数或缺粮天数 | 鱼/日 |
| 每日交易次数 | 当日已成交的 `trade` 事件数量 | 现有 `daily.trades`；不是订单数 | 次/日 |
| 每日制造渔网 | 当日 `craft` 事件数量 | 现有 `daily.nets_made`；不是现存渔网数 | 张/日 |
| 计划主要活动人数 | 对当天每个有计划的居民，以四时段中频次最高的动作分组；平票取首个出现的动作 | 需从已归档的每日意图/计划增加统计；第 0 天无计划显示缺失 | 人 |
| 已执行劳动时段 | 当日已提交的行动事件按动作和 `blocks` 汇总；失败、无效及其他事件不混入 | 现有事件可推导，需新增每日分类汇总并核对事件语义 | 时段/日 |

**计划和执行必须明确区分。** 截图中右侧曲线可复现为“计划主要活动人数”，但不能命名为“实际劳动人数”或“各类工作时段”。可在图表提供“计划主要活动人数 / 已执行劳动时段”切换，默认前者以对应 Mesa 原型；两种模式分别显示单位、来源和说明，不在同一坐标轴混用。

- 第 0 天没有计划时显示“未记录”，不要画成全员休息或 0 人。
- 未来新动作按数据驱动的分类和图例展示，未知动作显示“其他 / 原始动作名”，不丢弃数量；动作多时默认展示主要类别、可筛选，其余聚合为“其他”。保持分类规则版本，旧数据可解释。
- 缺失、未归档、未计算与真实的 0 分开表示；不使用占位数字冒充数据。空值时图表断线并给出说明。
- 复盘中的食物及建议参数单位同样做毫鱼到鱼的换算；保留原始值用于核对。
- 实际事件统计、计划活动分组、居民退出与非活跃状态的口径需要在实现前以真实归档核实。已有 `shortage_days` 累计的是居民消费事件发生短缺的次数，不能直接标成去重后的“全岛缺粮天数”。

## 5. 每轮 LLM 经济复盘卡片

### 5.1 卡片位置与内容

在岛屿观察页最后固定保留一张“本轮经济复盘”卡片。卡片与独立的事实报告入口关联；事实统计继续由程序计算并可单独查看，不把 LLM 输出作为事实来源。

```text
┌ 本轮经济复盘 ─────────────────────── 已完成 ──────┐
│ 运行：当前轮次             数据截至：第 30 天      │
│                                                    │
│ 本轮总结                                           │
│ 模型对生产、消费和资源变化的解释……                 │
│                                                    │
│ 主要观察                                           │
│ • [指标与数值：程序事实] 模型的解释  [查看依据]     │
│                                                    │
│ 下一轮资源建议                                     │
│ 参数：当前值 → 建议值；理由 / 假设 / 风险          │
│ 状态：待验证，未自动采纳                           │
│                                                    │
│ [查看完整事实报告]        [查看完整复盘]           │
└────────────────────────────────────────────────────┘
```

`summary` 展示模型总结；`claims` 显示由引擎提供的指标值、模型解释及对应的证据 ID；`proposal` 展示有依据的参数变化、假设和风险。若 `proposal` 为空，明确显示“本轮未提出参数调整建议”，不虚构建议。若建议因降级比例等原因仅供诊断，展示 `blocked_reason` 和限制，不显示可采纳状态。模型解释应标识为推断，不把相关性写成已经验证的因果关系。已归档英文总结先按原文显示；新复盘按现有提示词请求中文，不在页面加载时额外发起翻译调用。

### 5.2 状态与运行生命周期

| 状态 | 卡片行为 |
|---|---|
| 待开始 / 运行中 / 暂停 | 显示“轮次结束后自动生成”；可查看当前统计，但不显示未来的最终总结。 |
| 已完成 / 经济坍缩，事实报告就绪 | 先显示事实报告入口；LLM 正在准备或生成时显示进度。坍缩视为终态并提示实际结束日。 |
| `schema_validated` | 展示结论和受约束的候选建议，说明仍需后续验证且未采纳。 |
| `no_change` | 展示总结与依据，明确没有参数调整建议。 |
| `diagnostic_only` | 展示诊断、保留的建议及受限原因，不显示为可采纳。 |
| `failed` / `unavailable` / `interrupted` | 展示安全的错误类别或原因、事实报告入口和处理说明；不能把错误信息伪装成模型总结。 |
| 已禁用自动复盘 / 旧运行未启用 | 明确显示未启用或不可用；事实报告仍可查看。 |

现有自动复盘已有独立调用预算，当前最多 2 次请求（含纠错）；本方案延续现有配置与成本语义。**浏览页面、切换运行、回放或刷新都只读归档，不触发 LLM 调用，不自动重复失败或结果不确定的请求，也不自动应用建议。** 如果以后要支持重试，须另行设计明确的用户操作、预算、去重和不确定请求处理；不属于本次 MVP。

### 5.3 回看和历史轮次

页面级 `run_id` 决定所有图表、事实报告和复盘归属，切换运行时清空旧轮次内容并获取新数据。用户回看该轮历史日期时，图表不泄漏所选日之后的数据；最终复盘卡片显示“当前正在回看历史，最终复盘基于整轮”，默认折叠并提供“回到最新查看”入口，避免把最终分析误认为该日已知事实。最终日期或用户回到最新时显示本轮完整复盘。历史运行没有报告时如实显示，不通过 GET 自动补生成。

## 6. 数据与模块设计

```text
Isleworks 引擎 / 决策
        ↓ 提交的世界快照、意图、事件、复盘归档
Storage（SQLite）
        ↓
Observation / Analysis（只读）：
  指标聚合、活动分类、版本与口径、居民和事件查询
        ↓
观察 API：运行摘要、日序列、受控样本、居民详情、复盘
        ↓
像素观察页 / 数据统计页 / 复盘卡片
```

- **域与引擎**：继续是资源变化和事件的权威来源；可视化不改变经济状态或生成额外事实。
- **归档与查询**：支持按运行、日期范围读取，保证一致的 `run_id`、结束日与规则/指标版本。历史归档不强制迁移，可按需从已有快照和意图计算；对确实无法计算的字段返回缺失及原因。
- **观察聚合**：复用现有 `analysis` 中可用的统计，在观察层增加按日活动统计。统一定义 `metric_id`、标签、单位、来源、规则版本，避免页面与 LLM 复盘各算一套不同的值。
- **观察 API**：现有接口优先兼容；如需拆分，按概览/指标序列/群体样本/居民详情/事实报告与复盘组织。接口名称和字段属于实现设计，当前并非都已存在。筛选、分页和响应大小上限须定义明确，不向总览默认返回全部居民或全部历史事件。
- **前端展示**：独立实现可复用的像素画布、统计图表和复盘卡片；通过同一个运行与日期上下文读取，不依赖临时原型的硬编码数据。
- **自动复盘**：复用现有 `Runner`、`evolution`、归档和只读报告接口；不在页面中重新生成总结，也不把建议直接写入配置。
- **Mesa**：本次借鉴图表交互与统计表现；保留未来做只读 Mesa 适配器的可能，不作为主页面运行所需依赖。是否引入图表库由实施时在浏览器兼容、离线运行和维护成本之间评估。

### 6.1 拟议只读数据契约示例

以下仅用于对齐信息，不是已有 API：

```json
{
  "run_id": "示例运行 ID",
  "as_of_day": 2,
  "last_committed_day": 2,
  "status": "paused",
  "metrics_version": "1",
  "series": [
    {"day": 0, "food_stock_millifish": 12000, "planned_activity_counts": null},
    {"day": 1, "food_stock_millifish": 8000, "planned_activity_counts": {"gather": 6}}
  ],
  "semantics": {"planned_activity_counts": "当日计划中出现最多的动作；平票取首个"}
}
```

示例数值用于说明结构；统计页可选择其他日期。接口应显式携带时间边界、单位、版本和缺失值语义。事实与模型复盘按已有结构分别读取。

## 7. 规模与性能策略

- 小规模可绘制全部真实居民；大规模用真实人数聚合和有标识的代表性样本。抽样不替代完整数据，按 ID 或筛选条件获取居民详情。
- 统计序列按日/时间窗口查询，避免每次刷新加载整个归档与所有个体；使用响应范围限制和分页。可先保证正确性，再根据实测决定是否引入聚合缓存或增量更新；缓存需以运行、日期、指标版本和规则版本隔离，并可从归档重建。
- 实验中 10,000 条合成居民 JSON 约 1.84 MB，已经提示全量刷新有成本，但该数字不是生产性能基准，也没有覆盖浏览器端到端、并发、移动端或真实 10,000 Agent 运算。
- 以 6、100、10,000 条合成记录验证统计一致性与响应大小，记录浏览器加载、更新时间、关键交互及设备条件；验收阈值实施前根据目标机器基线确定。大规模实验不能虚构交易、价格或模拟因果。
- 新动作、资源和指标应可新增映射或分类并有通用降级；第一版使用简单配置即可，不提前建设复杂插件系统。

## 8. 分阶段实施

### 阶段一：接入像素主界面与观察上下文

1. 将临时原型中确认可用的视觉与交互重建或有选择地迁入项目；代码、素材与访问路径归入正式项目，不依赖 `/private/tmp`。
2. 连接真实运行选择、当前状态、历史日期、居民和事件；复用现有启动/暂停/继续/单步能力并保留其安全限制。
3. 提取共用的 `run_id`、所选日期和最新状态；明确位置与采样为示意。

### 阶段二：数据统计页面

1. 建立可核对的观测汇总与日期范围查询；复用现有每日指标，补充计划活动与执行时段统计。
2. 实现摘要、食物存量、计划活动趋势、产消和活跃人数等图表；给出单位、说明、空状态和数据表。
3. 加入群体/居民按需读取，并对合成规模和历史缺失数据进行验证。

### 阶段三：页面末尾的复盘卡片

1. 复用现有事实报告和 LLM 复盘归档接口，覆盖自动生成、完成、无建议、仅诊断、失败、禁用和中断等状态。
2. 展示总结、证据、参数变化、假设和风险；支持查看事实报告与完整复盘。
3. 验证历史回看、切换运行、结果未就绪和异步更新，不因页面行为额外调用 LLM 或应用参数。

各阶段可分别审查；这是同一目标下的实施顺序，不要求用户在页面里手动触发复盘。

## 9. 验收标准

1. 岛屿观察和数据统计可在同一运行上下文中切换；刷新、切换运行、回看日期后数据显示正确，页面没有交叉轮次污染。
2. 对现有 30 日归档，逐日食物存量与快照一致；每日产消、交易、缺粮和渔网制造与已提交事件核对；毫鱼/鱼转换正确。
3. 计划活动人数与归档计划匹配，平票及第 0 天口径明确；已执行劳动时段与行动事件匹配，两者标签、单位和来源清晰区分。
4. 完成或坍缩后，事实报告与已归档的自动 LLM 复盘可展示；有建议、无建议、受限、失败、未配置、已禁用及中断均有清楚状态；建议不会自动应用。
5. 历史日不展示未来日统计为当时已知数据；最终复盘可明确标识属于整轮，默认不泄漏为历史当日结论。
6. 没有运行、无计划、数据缺失、旧归档及新动作均有合理提示，不能以 0 或默认动画冒充缺失事实。
7. 用合成的 6、100、10,000 居民数据检验总数、分类、采样和按需查询；记录测量环境和响应大小，不宣称已完成同规模 LLM 或经济运行。
8. 页面的读取、回放和刷新不发起模型请求；自动复盘单独按现有生命周期执行。验证使用离线测试与模拟传输，不读取密钥或发起真实付费调用。
9. 运行项目现有测试，并增加必要的指标口径、报告状态、运行切换和前端交互测试；完成浏览器桌面与窄屏验证，并记录未覆盖项。

## 10. 当前不纳入

- 真实的多地区地理模型、路网和运输成本。
- 为所有动作制作专属动画；像素素材和动画在通用表现上逐步扩展。
- 以 10,000 个 LLM Agent 跑完整经济实验、跨轮自动采纳参数、实时多人协作。
- 将 Mesa 作为生产主界面或重写经济引擎。

这些是未来可能的方向，并非已实现或已验证的能力。
